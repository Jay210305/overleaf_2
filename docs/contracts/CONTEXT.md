# Interface Contract Context

Inputs: [Catalog](README.md), relevant [architecture](../planning/02-architecture.md), one selected task and producer/consumer requirements.
Process: inspect the relevant schema and examples; revise interface, failure/authorization behavior and direct consumer task acceptance together. Record breaking changes in [Decisions](../planning/09-decisions.md).
Outputs: design contracts and consistent [OpenAPI](openapi.json)/[HTTP operation index](http-operations.md).
Human check: contract text establishes a design baseline, never runtime evidence. See [impact routing](../map/effects/CONTEXT.md).
