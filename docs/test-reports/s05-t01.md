## Scope and acceptance evidence

- `POST /api/v1/projects/:projectId/uploads/presign` requires the project EDIT guard and session CSRF, checks a strict filename, extension/MIME pair, parent, sibling collision, 25 MiB file limit, 100 MiB project limit and 2000-node limit. It records a project/actor-bound durable intent and returns a 300-second PUT URL for a unique private staging key.
- `POST /api/v1/projects/:projectId/uploads/complete` requires current EDIT permission and an idempotency key. It compares backend object size and a SHA-256 computed from a bounded read, then checks UTF-8 text or binary signatures. Text begins as a canonical Yjs update; binary bytes are copied to a server-controlled content-addressed key. One database transaction creates the node and increments the project revision. Repeated completion with the same key returns the same node; another key conflicts.
- `tests/integration/s05-t01.test.ts` exercises valid bibliography bytes, Yjs recovery, unsafe names, unsupported types, project byte quota, claimed and actual oversize/mismatch, foreign project and intent, viewer denial, revoked editor, concurrent retry and the pending-intent FK behavior. `tests/regression/pro-05/s05-t01.test.ts` checks valid private PNG bytes and malformed PNG rejection. `tests/regression/pl-07/s05-t01.test.ts` checks the capped object read.
- S05-T01 has no ZIP parser; archive traversal, symlink and decompression-bomb rejection belong to S05-T03/S05-T08. The route rejects ZIP extensions. Upload progress/cancel UI belongs to S05-T02. This report covers the API slice of PRO-05 and PL-07, not those entire features.
