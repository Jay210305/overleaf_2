**Status:** Done; independent co-maintainer accepted on 2026-10-12. **Branch:** `feature/identity-permissions` tracking `origin/feature/identity-permissions`. **Base:** accepted S02-T09 closure commit `bbdc3b6` (sprint base `b75ef65`). **Environment:** Windows, Node 24, pnpm 11.25.0, local PostgreSQL 17, Redis 7, Mailpit and Edge browser. **Actual effort:** not measured.

## Scope and behavior

- Authenticated `/api/v1/me` read/update persists the current user's display name, locale and timezone. `/me/preferences` read/update persists locale, IANA timezone, theme and validated editor/notification settings in the existing `user_preferences` table. The settings page exposes display name, locale, timezone and theme, loads saved values after reload and applies the selected theme. Existing email is shown read-only; avatar upload is S02-T11, and no email-change workflow is claimed.
- `/me/sessions` lists only the caller's active sessions using a bounded cursor; the browser can load subsequent pages. A single session can be read or revoked only by its owner. Revoking the current session clears its cookie; revocations are audited in the same transaction. All writes check the exact Origin and matching CSRF secret, then recheck current session state inside the mutation transaction. Malformed input returns 400; expired sessions return 401; disabled accounts or forged Origin/CSRF return 403; foreign or absent session IDs return 404. Redis limits of 60 reads or 30 writes per IP per minute provide 429 with `Retry-After`.
- The browser settings page validates responses with shared Zod schemas. React StrictMode's repeated effect shares the one `/auth/session` rotation promise; the initial Edge run exposed this race and failed with 401, then passed after the fix. The static OpenAPI copies mark these live methods IN_PROGRESS; generation/DTO parity remains GAP-12.
