## Scope and acceptance evidence

- `apps/jobs/src/sync/apply-changes.ts` (`createGitHubApplyService`) composes the S12-T03 pull plan instead of re-planning: a `conflict` plan rejects the whole apply with 409 REMOTE_CONFLICT and writes nothing; a `synced` plan is a no-op that returns the checkpoint revision. Only `add`/`update`/`delete` entries are applied, in path order.
- Canonical text mutations go through the injected `CanonicalTextPort`, structurally satisfied by the API's real `DefaultTextDocumentService` (the integration suite injects the real service, not a stub). Text updates build a bounded replacement delta from the replayed current state via `buildReplacementUpdate` (delete-all + insert, anchored to the current state vector so the canonical apply's base-vector guard still applies); malformed canonical state is 409 REVISION_CONFLICT, never a fabricated delta. No path writes Yjs state directly and no snapshot DB replacement bypasses live Yjs.
- Every remote byte is fetched and validated **before the first mutation**: `classifyArchivePath` (extension policy), `verifyTextContent` (strict UTF-8, no NUL) / `verifyBinaryContent` (PNG/JPEG/PDF/TTF/OTF signatures), per-file > 25 MiB → 413 QUOTA_EXCEEDED, policy rejection → 422 UNSUPPORTED_CONTENT, provider failure → mapped (429 RATE_LIMITED, 502 PROVIDER_UNAVAILABLE, 401 CREDENTIALS_MISSING). An add whose ancestor path is a local file is 409 REVISION_CONFLICT (checked at plan time and again inside the insert transaction).
- Metadata is preserved: updates keep node id/parent/name/mime/content_kind and only change canonical text (`size_bytes` follows the remote byte length) or `blob_key`/`size_bytes` for binaries; binaries are stored under content-addressed `projects/<projectId>/blobs/<sha256(bytes)>` keys; deletes are soft (`deleted_at`) and clear `projects.main_file_id` when the remote deletes the main file; adds create missing folders in one transaction. Concurrent local adds surface as `23505`/CONSTRAINT_VIOLATION → 409.
- Frozen-state guard (`verifyFrozenLocal`): adds require the path to still be absent; update/delete require the exact frozen kind and fingerprint. A concurrent local edit/delete/kind change during the byte fetch or between entries aborts with 409 REVISION_CONFLICT with nothing applied; the concurrent edit is preserved, never overwritten.
- Failure compensation: each mutation records an undo step (reverse canonical text replacement, soft-delete added node/folders, restore previous `blob_key`/`size_bytes`, undelete + restore `main_file_id`). A mid-apply failure runs the journal in reverse and rethrows; the original integration case proves restoration when no other editor writes during rollback. The new concurrent case preserves the collaborator's edit by skipping an unsafe text undo, but leaves GAP-34 open for partial recovery.
- Final transaction commits together: anchor detachment (`detachAnchorsForChangedNodes` for every changed node id — open comments → `detached`, pending suggestions → `conflict`), a `Post-pull state` structural revision (`source: github-pull`) that freezes the applied tree and bumps `current_revision`, and the agreement update (`sync_base_manifest` rebuilt from post-apply local fingerprints + accepted remote SHAs, `sync_cursor`, `last_synced_revision`). `keep-deleted` resolutions are carried forward so the next pull does not resurrect a deliberately deleted file.
- Invalidations: typed `SyncInvalidationEvent` emissions in path order — `file_changed` with the bounded Yjs delta for text mutations (the integration suite applies it to a replica doc seeded with the pre-pull state and asserts convergence to the remote text), `file_changed` with `updateBase64: null` for binary/tree changes, `file_deleted` for deletes. Delivery is best-effort: publish failures are counted, logged without secrets and never roll back committed state (asserted).
- Shared anchor detachment: `detachAnchorsForChangedNodes` moved from `apps/api/src/modules/history/restore-metadata.ts` to `packages/db/src/repositories/review-anchors.ts` (exported from the package index) so restore and sync keep one implementation; the single API importer (`restore.ts`) was updated and the old file deleted. `github-pull.ts` gained only exports (`mapProviderError`, `parseSyncBase`, `localFilesFromRevision`, `buildAgreement`) plus the two apply-time error codes (`REVISION_CONFLICT`, `UNSUPPORTED_CONTENT`).
