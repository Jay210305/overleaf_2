# S08-T03 — Sharing and role management UI

**Status:** IN_PROGRESS; implementation and scoped verification are ready for independent co-maintainer review. **Branch:** `codex/sprint-08-sharing-comments-chat` tracking `origin/codex/sprint-08-sharing-comments-chat`. **Base:** `a568117` (`origin/main`, after S07). **Environment:** Windows, Node 24.20.0, pnpm 11.25.0, Docker Compose PostgreSQL/Redis/MinIO/Mailpit and Playwright Edge. **Actual effort:** Not measured.

## Implemented and observed

- The workspace opens a sharing dialog from the project page. All current members can read owner and active-member roles; only OWNER sees invitation/link metadata and controls to invite, change a member role, remove a member, create a bounded link or revoke an invitation/link. The dialog paginates all three lists, focuses Close on opening, supports Escape, and leaves controls available after a failed mutation for retry.
- `GET /projects/{projectId}/members` returns a bounded active-member page. OWNER-only PATCH/DELETE member routes recheck current owner, session and CSRF inside the transaction, reject foreign/inactive/owner targets and invalid roles, and write audit events. A role patch makes a link-derived grant an independent owner-managed membership. PostgreSQL tests confirm denied crafted requests do not change membership.
- Browser invitation and share-link routes remove token fragments immediately and submit tokens in JSON with session CSRF. A newly created share-link secret is displayed once in the dialog and kept in component memory only. Real Edge service flow exercised owner role change/removal, Mailpit-backed invitation creation, one-use link creation, a separate signed-in recipient's redemption, and project access.
- The contract DTOs, OpenAPI copies and HTTP contract describe the member routes. The earlier S08-T02 API rate limiter was missing share-link scopes in its Redis limit table; a real Redis regression exposed this during the Edge flow and the scopes were added.
