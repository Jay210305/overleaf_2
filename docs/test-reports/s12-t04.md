# S12-T04 — Push frozen revision with remote guard

**Status:** DONE — accepted by the user 2026-10-17; implementation complete and the full local gate passes. **Branch:** `codex/sprint-12-github-sync` (tracking `origin/codex/sprint-12-github-sync`). **Environment:** Windows, Node 24, pnpm 11.25.0, local PostgreSQL and MinIO. **Actual effort:** Not measured.

## Implemented slice

`apps/jobs/src/sync/github-push.ts` checks the current OWNER/EDITOR role, linked repository and branch, active encrypted server-held credential, exact source revision/project, stored canonical manifest hash and each frozen item. Text bytes come from `revision_items.text_bytes`; binaries are bounded reads from content-addressed objects with size and SHA-256 verified before any provider write. A legacy revision without frozen content or a missing/tampered blob is rejected.

The GitHub REST writer creates blobs, a tree based on the verified remote tree (preserving unrelated paths and deleting only previously synced paths absent from the source), and a commit whose sole parent is the caller's `expectedRemoteSha`. It reads the branch head first, then updates the ref with `force: false`. A remote advance or GitHub's non-fast-forward response yields `REMOTE_CONFLICT`; 401, rate limiting, missing permission and other provider failures are surfaced without advancing the local cursor. After a successful ref update, cursor, revision, agreement and a redacted actor/base/source/result audit event commit together. A database failure after the remote ref update returns an error, not a false `synced` result; cross-system recovery remains for S12-T07.
