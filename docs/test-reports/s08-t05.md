## Implemented and observed

- `GET/POST /api/v1/projects/:projectId/chat/messages` use the existing `chat_messages` table. The API validates bounded text, returns typed newest-first cursor pages, and rechecks session, CSRF, project and writer role inside the insert transaction. Reviewer writes are accepted; viewer reads/writes, foreign projects, malformed cursors, unsafe or oversized text, and invalid CSRF are denied.
- The project-scoped read-only WSS endpoint checks exact Origin, current cookie and COMMENT permission on upgrade, and rechecks active session and membership on each poll. It derives `chat.created` invalidation hints from committed chat rows; message bodies stay in REST responses. Revocation closes an open chat socket.
- The mounted workspace panel reads durable history, posts with session CSRF, loads older pages, refreshes on WSS hints, and reconciles on reconnect, focus and a 30-second interval. Loaded older pages remain visible after refresh. Text renders through React text nodes. A missed hint is recoverable from REST.
- The Edge journey used two signed-in contexts: an owner posted and a reviewer received the new message through the socket before periodic reconciliation. Scoped axe checks on `.project-chat` found zero serious or critical violations.
