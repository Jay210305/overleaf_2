# S14-T02 — Create authenticated Git bridge service

**Status:** PASS. **Branch:** `codex/sprint-14-git-and-optional-features` tracking `origin/codex/sprint-14-git-and-optional-features`. **Base:** `codex/sprint-13-reference-providers`. **Environment:** Linux (x86_64), Node 26+, pnpm 11.25.0. **Actual effort:** 8 h.

## Scope and acceptance evidence

- Implemented authenticated Git Smart HTTP backend service in `apps/git-bridge/src/server.ts` and `apps/git-bridge/src/auth.ts`:
  - Smart HTTP `info/refs` ref discovery advertisement (`# service=git-upload-pack`, `# service=git-receive-pack`, pkt-line formatting with `0000` flush pkt).
  - High-entropy Git Personal Access Tokens with SHA-256 storage, scoped permissions (`git:read` and `git:write`), expiration handling, and immediate revocation.
  - Server-side authorization verifying project membership: OWNER/EDITOR allowed for push (`git-receive-pack`); VIEWER permitted for read (`git-upload-pack`) but denied 403 on push; non-members receive 404 `RESOURCE_NOT_FOUND` to prevent repo enumeration.
  - Complete secret redaction: database credentials, session cookies, and internal passwords are never exposed in Git bridge headers or response payloads.
  - Basic authentication parsing supporting Git CLI `username:token` interactions and `WWW-Authenticate: Basic realm="LaTeX Collaborative Git Bridge"` challenges.
