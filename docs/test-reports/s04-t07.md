## Scope and behavior

- Implemented `apps/api/src/modules/history/checkpoint.ts` and registered checkpoint routes in `apps/api/src/server.ts`:
  - `POST /api/v1/projects/:projectId/checkpoints`: declared `projectAction: "EDIT"`. Freezes the current active project tree into an immutable structural revision, generating a deterministic SHA-256 manifest hash and manifest key pinning text and binary file hashes without creating one full revision per keystroke.
  - `GET /api/v1/projects/:projectId/checkpoints`: declared `projectAction: "READ"`. Lists project revisions ordered newest to oldest.
  - `GET /api/v1/projects/:projectId/checkpoints/:revisionNo`: retrieves a specific revision and manifest.
  - `GET /api/v1/projects/:projectId/checkpoints/compare`: compares two revisions returning added, removed, modified, and unchanged nodes (`COL-10`).
- Enforced key boundaries:
  - Keystroke edits via `PUT /text` do NOT create `project_revisions` rows, eliminating keystroke bloat.
  - Revisions are created strictly when an explicit checkpoint is requested (e.g. manual save or compile checkpoint).
  - VIEWER is denied with 403 `PROJECT_PERMISSION_DENIED` on checkpoint creation (`COL-03`).
  - Manifest hash matches the deterministic SHA-256 canonical JSON representation (`NFR-06`).
