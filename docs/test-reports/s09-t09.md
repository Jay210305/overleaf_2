# S09-T09 — Implement archive trash and permanent deletion

**Status:** IN_PROGRESS (task implementation complete; pending sprint completion). **Branch:** `codex/sprint-09-history-review` tracking `origin/codex/sprint-09-history-review`. **Base:** `main`. **Environment:** Linux (x86_64), Node 24+, pnpm 11.25.0, local Docker Compose PostgreSQL 17, Redis 7. **Actual effort:** 8 h.

## Scope and acceptance evidence

- Implemented project lifecycle endpoints and service in `apps/api/src/modules/projects/lifecycle.ts`:
  - `POST /api/v1/projects/:projectId/archive`: moves active project to `archived` status (requires OWNER).
  - `POST /api/v1/projects/:projectId/unarchive`: moves archived project back to `active` (requires OWNER).
  - `POST /api/v1/projects/:projectId/trash`: moves active/archived project to `trashed` status (requires OWNER).
  - `POST /api/v1/projects/:projectId/restore-trash`: restores trashed project to `active` status (requires OWNER).
  - `DELETE /api/v1/projects/:projectId/permanent`: owner-confirmed permanent deletion that verifies project is already trashed, validates title confirmation (`confirmTitle`), and permanently deletes project with cascading entity deletion.
- Updated project authorization guard in `apps/api/src/plugins/require-session.ts` to allow `RESTORE` and `DELETE` actions on non-active projects, preserving protection against unauthorized access.
- Implemented accessible UI components in `apps/web/src/features/projects/lifecycle.tsx` (`ProjectLifecycleActions` and `PermanentDeleteDialog` with title-match validation).
- Added comprehensive test suites:
  - `tests/integration/s09-t09.test.ts`: exercises archive, unarchive, trash, restore-trash, non-owner denial, trashed precondition enforcement, title mismatch validation, and permanent deletion.
  - `tests/regression/pro-08/s09-t09.test.ts`: verifies PRO-08 requirement distinguishing archive from trash and enforcing owner confirmation for permanent deletion.
