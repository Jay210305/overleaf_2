**Status:** IN_PROGRESS (execution limits complete; pending sprint completion). **Branch:** `codex/sprint-06-trusted-compilation` tracking `origin/codex/sprint-06-trusted-compilation`. **Base:** `origin/main` at `35a9d57`. **Environment:** Linux (x86_64), Node 24.19.0, pnpm 11.25.0, local Docker Compose PostgreSQL 17, Redis 7, MinIO and Mailpit. **Actual effort:** 8 h.

## Scope and acceptance evidence

- Implemented `apps/tex-executor/src/execute.ts` providing execution limit resolution and bounded execution runner `executeWithLimits`.
- Enforces strict limits:
  - Clamps client-supplied arbitrary limits to server policy ceilings (timeout <= 60 s, memory <= 512 MiB, CPU <= 1 core, max output <= 25 MiB).
  - Automatically aborts compilation tasks exceeding 60-second limit and maps to `timed_out` status with exit code 124.
  - Rejects compilations generating artifacts exceeding 25 MiB with `failed` status and descriptive diagnostic message.
  - Abort signals (SIGTERM or client cancellation) propagate to subprocesses and yield `cancelled` status.
- Added test suites:
  - `tests/integration/s06-t05.test.ts`: validates parameter clamping, execution timeout abort, output size ceiling rejection, and clean cancellation handling.
  - `tests/regression/cmp-04/s06-t05.test.ts`: verifies `timed_out` status mapping conforming to lifecycle contract.
  - `tests/regression/nfr-07/s06-t05.test.ts`: verifies that server bounds prevent unbounded CPU or memory allocation.
  - `tests/regression/pl-07/s06-t05.test.ts`: verifies finite resource caps against infinite timeouts or file outputs.
