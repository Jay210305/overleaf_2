# S02-T03 — Password recovery

**Status:** Implemented and locally tested; independent co-maintainer review pending. **Branch:** `feature/identity-permissions` tracking `origin/feature/identity-permissions`. **Base:** accepted S02-T02 closure commit `e01b278` (sprint base `b75ef65`). **Environment:** Windows, Node 24, pnpm 11.25.0 via the installed CLI, PostgreSQL 17 and Mailpit in local Compose. **Actual effort:** not measured.

## Scope and behavior

- `POST /api/v1/auth/password/forgot` requires exact Origin and custom CSRF header. Valid known and unknown addresses receive 202 with the same body and content type. Only a verified, enabled account with a password gets a reset email. With no configured SMTP sender, every address receives 503. Delivery failure removes the undelivered token and still returns 202.
- The 32-byte random token is stored as a SHA-256 hash, expires after one hour and is invalidated by a newer request. Mailpit verified an actual SMTP message carrying a link with the token in the URL fragment.
- `POST /api/v1/auth/password/reset` validates the token and new password, rechecks the token and account under PostgreSQL locks, updates the Argon2id password hash, consumes remaining reset tokens and revokes every session in one transaction. Malformed input returns 400, used/expired/unknown tokens return 401, and disabled accounts return 403.
- Public signup remains disabled. The reset page belongs to S02-T05, authenticated password change to S02-T10, and distributed auth rate limiting with 429 to S02-T06.

Synchronous SMTP work makes latency differ, so full timing indistinguishability has **not** been established; see GAP-14. Distributed 429 abuse limiting remains S02-T06. Independent co-maintainer review is required before this task can be marked `done` or S02-T04 starts.
