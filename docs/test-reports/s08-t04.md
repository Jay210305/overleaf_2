# S08-T04 — Anchored comments and replies

**Status:** DONE; independent co-maintainer review confirmed 2026-10-15 in [sprint progress](../progress/sprint-08.md). **Branch:** `codex/sprint-08-sharing-comments-chat` tracking `origin/codex/sprint-08-sharing-comments-chat`. **Base:** `a568117` (`origin/main`, after S07). **Environment:** Windows, Node 24.20.0, corepack pnpm 11.25.0, Docker Compose PostgreSQL/Redis/MinIO/Mailpit. **Actual effort:** Not measured.

## Implemented and observed

- `POST /projects/{projectId}/comments` creates a durable thread from a validated serialized `Y.RelativePosition` anchor plus `selectedText` context; creation rejects anchors that do not resolve against current canonical text with 409 `REVISION_CONFLICT` rather than attaching to unrelated source.
- `POST /comments/{commentId}/replies` appends a reply; `PATCH /comments/{commentId}` flips `open`/`resolved`; `DELETE /comments/{commentId}` allows OWNER or the comment author; `GET /comments` pages threads with replies and per-read anchor resolution (`detached`/`detachedReason: range_changed`, `start`/`end`).
- Resolution (`apps/api/src/modules/comments/anchors.ts`) requires both ends in the file's `content` root, `start < end`, and an exact `selectedText` match; a deleted range reports `detached: true` instead of sliding to adjacent source. Role enforcement is two-layer: the `COMMENT` project guard (OWNER/EDITOR/REVIEWER, VIEWER denied) plus an in-transaction writer recheck with session/CSRF and permission-aware delete.
- `CommentThread` (`apps/web/src/features/review/comment-thread.tsx`) selects canonical source text, builds relative anchors client-side, and exposes reply/resolve/reopen/delete with 403/409-specific messages.
- Schema: `packages/db` collaboration tables carry `selected_text`/`mentions` (migration `0011-comment-context.sql` extends `0002-support.sql`); contracts validate anchors as Yjs relative positions with bounded sanitized bodies (10,000 chars) and project-member mentions.
- **Finding fixed in this slice:** resolving absolute positions *before* the first typed `doc.getText("content")` access on an update-decoded doc compares against a stale Yjs root wrapper, so every valid anchor detached (`startTypeEq: false` with correct indexes 7/13 and matching text). Reproduced deterministically (4 consecutive focused failures) plus a 10/10 isolation experiment; reading the root first stabilizes the wrapper and all 5 scoped tests pass repeatedly (4 consecutive green runs after the fix, then green again after formatting).
