## Scope and acceptance evidence

- Implemented `freezeCompilationRevision` in `packages/db/src/repositories/compilations.ts` and re-exported in `apps/jobs/src/compilation/snapshot.ts`.
- Binds compile jobs durably to immutable structural revisions:
  - If `targetRevisionId` is omitted, captures the current active project tree (all text and binary nodes, root files, compiler settings, image digest) into a monotonic structural revision.
  - If `targetRevisionId` is supplied, validates existence and project ownership, binding directly to the specified revision without duplication. If invalid or foreign, fails with 404 `RESOURCE_NOT_FOUND`.
- Verifies that subsequent changes to the project tree (such as adding nodes or updating text) do not modify the frozen revision input or its immutable `manifest_hash`.
- Added test suites:
  - `tests/integration/s06-t02.test.ts`: exercises snapshot creation, immutability under subsequent project modifications, binding existing targetRevisionId, and rejecting invalid targetRevisionId with 404.
  - `tests/regression/nfr-06/s06-t02.test.ts`: validates that the compile job source revision binds exactly to the immutable manifest hash.
  - `tests/regression/cmp-01/s06-t02.test.ts`: verifies that the frozen revision manifest contains required compiler metadata and main.tex ready for TeX Live execution.
