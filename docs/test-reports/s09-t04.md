## Scope and acceptance evidence

- Implemented separate suggestion model and REST endpoints in `apps/api/src/modules/review/suggestions.ts` (`POST /api/v1/projects/:projectId/suggestions`, `GET /api/v1/projects/:projectId/suggestions`, `GET /api/v1/projects/:projectId/suggestions/:suggestionId`).
- Guarded suggestion creation with action `SUGGEST` (granted to OWNER, EDITOR, REVIEWER; rejected for VIEWER with 403).
- Maintained invariant that reviewer suggestions (insert, delete, replace) persist independently in `suggestions` without modifying canonical text nodes or text documents.
- Implemented `EditorModeSelector` UI component in `apps/web/src/features/review/mode.tsx` providing accessible mode switching between Edit, Review, and View based on user role capabilities.
- Added test suites:
  - `tests/integration/s09-t04.test.ts`: exercises insert/delete/replace suggestion creation by REVIEWER, verifies canonical text immutability, lists suggestions, and rejects VIEWER and outsider submissions.
  - `tests/regression/col-08/s09-t04.test.ts`: verifies COL-08 requirement that REVIEWER cannot directly overwrite canonical text via REST/WSS but can submit suggestions.
  - `tests/regression/col-09/s09-t04.test.ts`: verifies COL-09 requirement that suggestions track author, timestamp, anchor JSON, and initial `pending` status.
