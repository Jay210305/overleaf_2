## Scope and acceptance evidence

- `POST /api/v1/projects/imports/presign` (session-only guard) records a durable intent in the new `import_upload_intents` table (`packages/db/migrations/0007-import-upload-intents.sql`, next free number kept) and returns a 300-second PUT URL scoped to `imports/<actorId>/uploads/<uploadId>`. ZIP input over 25 MiB is rejected with 413; malformed input with 400. Missing/expired sessions give 401, forged Origin or CSRF and disabled accounts give 403.
- `POST /api/v1/projects/imports` with `{uploadId, title}` plus `Idempotency-Key` verifies the private object (existence, size, SHA-256 over a bounded read) and returns 404 for foreign uploads, 422 for expired intents and missing/mismatched bytes, 413 for objects over budget. It reserves one S05-T03 job **before** the server-only copy, copies verified bytes to `imports/<actorId>/jobs/<jobId>/source.zip`, verifies the copy, moves the job to queued and returns `202` with the import-specific `ImportJobView`. Same actor/key/input (including a crash between reserve and copy, and a completed intent) returns the same job; same key with changed title or fingerprint conflicts with 409 via the repository. `GET /api/v1/projects/imports/{jobId}` is actor-scoped (foreign jobs read as 404, malformed IDs as 400) and returns exactly `{id, status, title, projectId, errorCode, createdAt, updatedAt}` — never object keys. `validated` means ready for S05-T10, never that a project exists; no project, node or text row is created here.
- The project guard (`installProjectGuard`) learned a `sessionOnly` configuration so session-authenticated non-project routes can live under `/api/v1/projects/` with exact-Origin, current-session and mutation-CSRF checks; project routes are untouched.
- Storage GC cleans expired import staging through a new actor-scoped `imports/` phase backed by the intents table. Actor scoping keeps forged-clock and parallel runs from touching sibling actors or projects; project-scoped runs keep legacy project-only behavior; server-only job archives stay worker-owned and are never GC targets. The jobs runner accepts `--actor-id` alongside `--project-id`.
- Import DTOs (`ImportPresignRequest`, `ImportRequest` with title 1..200 matching the repository CHECK, `ImportJobView` with the six import statuses) live in `@latex-collab/contracts` and are enforced on both route output and tests. Both `openapi.json` copies gained the presign operation, the `ImportJobView`/`ImportPresignRequest` schemas, tightened `ImportRequest` title bounds and `IN_PROGRESS` import operations; `http-operations.md`, `http-api.md` and `storage-and-revisions.md` describe the live routes.
- `tests/integration/s05-t12.test.ts` (11 tests) covers presign scope/shape, session/Origin/CSRF/disabled denials, oversize declarations, byte-verified completion with same-key idempotency, crash-between-reserve-and-copy recovery, foreign/mismatched/changed-key/expired denials, oversized objects, foreign-job invisibility, the queued-to-validated handoff with no project created, expired-staging cleanup and the exact status shape. `tests/regression/pro-02/s05-t12.test.ts` and `tests/regression/pro-10/s05-t12.test.ts` cover the PRO-02 intake journey and the PRO-10 hostile traversal quarantine end to end. Because fixtures share local services and both validators and sibling tests run global passes, assertions wait for each job's terminal state instead of counting which pass moved it.
