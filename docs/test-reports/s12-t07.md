## Implementation

- `apps/jobs/src/sync/github-pull.ts`: the provider-error map now preserves `QUOTA_EXCEEDED` (413) instead of flattening an oversized remote blob to `PROVIDER_UNAVAILABLE` (502), matching the pull path's own size rejection. Surfaced by the T07 verification; no other behavior changed.
- `tests/integration/github-sync.test.ts`: drives `POST …/integrations/github/status` and `…/sync` through `createServer` with a controllable reader/writer and real PostgreSQL. Covers the CSRF/session guard, an expired credential (401 `CREDENTIALS_MISSING`), a remote advance at status time (409 `REMOTE_CONFLICT`), a stale expected SHA (409), an authorized pull that applies a remote add through the canonical service, an authorized push that advances the cursor only after remote success, and a non-fast-forward ref race (409) that leaves the cursor unchanged.
- `tests/integration/s12-t07.test.ts`: a stateful fake GitHub (blobs/trees/commits/refs, SHA-1 identities, non-fast-forward enforcement) backing the real services. Proves a push↔pull round trip returns `synced`; a stale expected SHA is rejected before any provider call; a ref that advances mid-push is a 409 with no forced ref and no audit event; an inactive credential contacts no provider; a remote advance at status writes no snapshot; and a concurrent local edit during remote-byte fetch aborts with 409 `REVISION_CONFLICT` while the local edit and cursor survive with no post-pull revision.
- `tests/regression/int-05/s12-t07.test.ts`: the REST boundaries map 401/429/403, oversized/inconsistent blobs, redirects and non-JSON bodies to typed codes; the non-force ref update sends `force: false` and maps 409 to `REMOTE_CONFLICT`; the conservative classifier never silently overwrites a shared path without a recorded agreement.
- `tests/integration/s12-t07-live.test.ts`: opt-in credentialed acceptance harness. It is skipped unless `GITHUB_LIVE_TOKEN`, `GITHUB_LIVE_REPO` (`owner/name`) and a non-default `GITHUB_LIVE_BRANCH` are present (optionally in the gitignored `.env.github-test`). When enabled it drives the **real** GitHub REST reader/writer through `createGitHubRestPushWriter`/`createGitHubRestReader` and the production pull/apply/push services to prove: (1) a frozen revision pushes to the real branch and a remote commit pulls back into canonical text; (2) a non-fast-forward advance returns 409 `REMOTE_CONFLICT` and leaves the real ref and cursor unchanged; (3) an invalid credential returns 401 `TOKEN_EXPIRED` with no ref change; (4) a local edit during real remote-byte fetch aborts with 409 `REVISION_CONFLICT`, keeps the concurrent edit and writes no post-pull revision. The token is never printed; `main`/`master` are refused unless `GITHUB_LIVE_ALLOW_DEFAULT=1`.

## Sprint e2e gate and integration fixes

Completing the sprint required a green browser gate over the whole product, which
surfaced one real cross-feature regression and two harness gaps:

- `apps/collab/src/server.ts`: the collaboration `WebSocketServer` was constructed
  with `{ server: app.server }`, so it claimed **every** upgrade request on the shared
  API HTTP server. The project-chat socket (`/api/v1/projects/{id}/chat/events`) runs a
  second `handleUpgrade` on the same socket, which `ws` rejects with "handleUpgrade()
  was called more than once with the same socket"; the chat client then saw the
  connection close before it was established and never reached "Live updates
  connected". The collab server now uses `noServer: true` with a path-aware upgrade
  listener that claims only its own root path (`/`) and removes the listener on stop.
  Verified by `pnpm test:e2e` (chat spec passes on all three browsers) and the
  collaboration journeys.
- `apps/web/src/features/projects/workspace.tsx`: the comment-anchor panel was only
  mounted in one branch of the workspace, so text files rendered without the panel and
  the anchored-comment journey could not observe created comments. The panel is now
  rendered with the text document.
- `tests/e2e/comments.spec.ts`: the detached-range assertion matched the comment body
  textarea through `getByText`, deleting the range before the create POST committed; it
  is now scoped to the anchor list and re-selects the file after reload (selection is
  component state).
- `tests/e2e/mixed-editing.spec.ts`: heading clicks are scoped to the live visual
  document (`live-visual-document`) so the now-present comment panel cannot create
  duplicate-text strict-mode violations.
- `package.json` (`dev`): the dev server now builds `@latex-collab/collab` before
  `tsx scripts/dev.ts`, matching `build`, so local Playwright e2e exercises the current
  collab sources instead of a stale `dist`.
- `tests/e2e/global-setup.ts` + `tests/e2e/rate-limit-flush.ts`: the browser suite
  performs many logins from one test-runner IP, which intermittently exceeded the
  per-IP auth rate-limit window (2/52 tests failed with "Too many attempts"). A
  Playwright global setup clears the `auth:v1:*` Redis counters during the run without
  changing production limits; the limiter itself stays exercised by S02-T06
  integration tests and the intercepted 429 in `auth-forms.spec.ts`.
