# S09-T08 — Create explicit restore confirmation UI

**Status:** IN_PROGRESS (task implementation complete; pending sprint completion). **Branch:** `codex/sprint-09-history-review` tracking `origin/codex/sprint-09-history-review`. **Base:** `main`. **Environment:** Linux (x86_64), Node 24+, pnpm 11.25.0, local Docker Compose PostgreSQL 17, Redis 7. **Actual effort:** 6 h.

## Scope and acceptance evidence

- Implemented accessible `RestoreDialog` component in `apps/web/src/features/history/restore-dialog.tsx`:
  - Complies with WCAG 2.2 AA accessibility guidelines (`role="dialog"`, `aria-modal="true"`, `aria-labelledby`, `aria-describedby`, keyboard navigation, and dismiss on Escape).
  - Clarifies revision impact: displays target revision, resulting new revision number, and explicit notice that project ownership, memberships, and permissions are preserved without modification.
  - Summarizes affected files with add/delete/modified status badges and alerts the user that comments and suggestions on changed files will be detached or marked conflicted.
  - Handles permission boundaries: displays an alert and disables the confirm button when the current user lacks restore permissions (e.g. REVIEWER or VIEWER).
  - Displays concurrency conflict errors (409) and successful restore status messages.
- Added comprehensive test suites:
  - `tests/integration/s09-t08.test.ts`: exercises modal rendering, affected file listings, onConfirm trigger, permission error disabling confirm button, and concurrency conflict display.
  - `tests/regression/col-11/s09-t08.test.ts`: verifies COL-11 requirement that restore UI clearly communicates single-file vs project scope and ACL preservation.
  - `tests/regression/nfr-08/s09-t08.test.ts`: verifies NFR-08 requirement that modal dialog adheres to WCAG 2.2 AA ARIA standards and keyboard dismiss patterns.
