# S08-T07 — Comment and chat safety and limits

**Status:** DONE; user review confirmed 2026-10-15 in [sprint progress](../progress/sprint-08.md). **Branch:** `codex/sprint-08-sharing-comments-chat` tracking `origin/codex/sprint-08-sharing-comments-chat`. **Base:** `a568117` (`origin/main`, after S07). **Environment:** Windows, Node 24.20.0, pnpm 11.25.0, local PostgreSQL fixture. **Actual effort:** Not measured.

## Implemented and observed

- `apps/api/src/modules/comments/safety.ts` (new): `assertSafeBody` rejects oversized (>10,000 chars), NUL-byte and executable bodies with 400 — forbidden tags, event-handler attributes, `javascript:`/`data:`/`vbscript:` link and URL-attribute destinations. `assertWriterRole` is now the single writer-role helper used by both comment and chat writers (behavior unchanged: VIEWER 403, non-member 404). `checkCommentCreationRate` enforces 30 comment/reply creations per author per project per 300 s sliding window with 429 `RATE_LIMITED`.
- `apps/api/src/modules/chat/safety.ts` (new): `assertChatBody` reuses the same body policy; `checkChatRateLimit` enforces 30 messages per author per project per 60 s sliding window with 429. Both limits are counted from committed rows inside the write transaction, so they hold across replicas without new tables or Redis.
- Wired into `POST /projects/:id/comments`, `POST .../comments/:id/replies` and `POST .../chat/messages` after the existing session/CSRF/project/role checks, so auth failures keep precedence and denied writes change no state.
- Pre-existing shape check found during work: the shared Zod body schema already rejects raw `<`, `>` and control characters, and `javascript:`/`data:` schemes. The new module is therefore a second server-side backstop for those vectors and the primary guard for `vbscript:` destinations (verified: `[click](vbscript:msgbox(1))` passes Zod and is rejected only by the safety layer). Safe Markdown is stored verbatim.
- Contract slice documented in `docs/contracts/http-api.md` (G2 Comment and Chat Safety Slice).
