# S05-T05 — Preview and download safe binary assets

**Status:** IN_PROGRESS, implementation complete 2026-10-16; independent co-maintainer review pending. **Branch:** `codex/sprint-11-visual-editor` tracking `origin/codex/sprint-11-visual-editor`. **Environment:** Windows, Node 24.20.0, pnpm 11.25.0, local PostgreSQL/Redis/MinIO. **Actual effort:** Not measured in hours.

## Scope and acceptance evidence

- `GET /projects/{projectId}/files/{fileId}/download` in `apps/api/src/modules/files/binary-download.ts` (registered in `server.ts`; matches the planned operation in [http-operations](../contracts/http-operations.md)): per-request READ authorization, BINARY FILE nodes only with project-scoped content-addressed keys, content hash re-verified against the key (422 on mismatch), 25 MiB bound. PNG/JPEG/PDF serve inline with their stored MIME; every other binary downloads as `application/octet-stream` attachment with `nosniff` and `no-store` — including legacy active HTML/SVG the upload policy would reject today, which therefore never executes in the trusted UI. Foreign/trashed/missing/non-binary nodes read as 404, bad sessions 401, unavailable storage 503, with no object keys in error bodies.
- `GET /projects/{projectId}/export?revisionNo=<n>` builds the deterministic S05-T04 source ZIP as an attachment download. Source export requires an explicit OWNER/EDITOR capability (reviewers/viewers receive 403, strangers 404, malformed revisions 400) per the authorization matrix in [http-api](../contracts/http-api.md).
- `BinaryPreview` in `apps/web/src/features/files/binary-preview.tsx` fetches only previewable images/PDFs with session credentials into revocable local blob URLs (response MIME re-checked client-side; failures show an unavailable placeholder). Active and non-previewable binaries render as attachment-only download links whose bytes are never fetched into the page; no `iframe`, `embed`, `srcdoc` or `innerHTML` path exists for them.
- The S05-T04 export builder moved to `packages/storage/src/source-export.ts` (new `./source-export` subpath; `+@latex-collab/db`, `+yjs` pinned) so the worker and the download route share one implementation; S05-T04 suites re-verified 6/6 against the new path.
- `tests/integration/s05-t05.test.ts` (4 jsdom tests): authorized image/PDF fetch rendering, attachment-only active types with zero fetch calls, failure placeholder.
- `tests/integration/s05-t05-assets.test.ts` (4 live tests): inline PNG bytes, attachment octet-stream for legacy HTML and fonts, foreign/text/session denials without key leakage, editor export vs viewer 403 vs bad-revision 404.
- `tests/regression/pro-05/s05-t05.test.ts`, `tests/regression/pro-06/s05-t05.test.ts`, `tests/regression/pl-07/s05-t05.test.ts` (6 tests): permitted preview without key material, text-as-binary refusal, byte-identical repeat ZIP downloads with `PK` magic, reviewer/stranger/malformed denials, inert active content with `nosniff` and no credential/key traces.
