# S08-T09 — Comment anchor and reply interactions

**Status:** IN_PROGRESS; implementation and scoped verification are complete, independent co-maintainer review pending. **Branch:** `codex/sprint-08-sharing-comments-chat` tracking `origin/codex/sprint-08-sharing-comments-chat`. **Base:** `a568117` (`origin/main`, after S07). **Environment:** Windows, Node 24.20.0, corepack pnpm 11.25.0, Docker Compose PostgreSQL/Redis. **Actual effort:** Not measured.

## Implemented and observed

- `CommentAnchors` (`apps/web/src/features/review/comment-anchors.tsx`) is the mounted review surface: for the selected TEXT file it loads canonical text plus the comment page and renders each thread with an anchored-range `<mark>` (`Comment anchor: {selectedText}`), body, status, member-resolved mentions, replies, resolve/reopen/delete controls, per-thread reply forms, and a select-then-compose form with member mentions. Detached threads show `Anchor unavailable: selected range changed.` with the body and replies intact and no highlight. Composer anchors are created from the server-loaded Yjs lineage (never a throwaway doc), and the loaded doc touches its root before use per the S08-T04 ordering finding.
- The panel mounts in `ProjectWorkspace` for selected `FILE`/`TEXT` nodes only; other nodes keep the previous details view.
- Server range-following is covered at the API: an insertion before a range shifts reported `start`/`end` (7/13 → 11/17); rewriting the source detaches with `range_changed` while body, replies and mentions stay visible.
