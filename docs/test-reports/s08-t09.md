## Implemented and observed

- `CommentAnchors` (`apps/web/src/features/review/comment-anchors.tsx`) is the mounted review surface: for the selected TEXT file it loads canonical text plus the comment page and renders each thread with an anchored-range `<mark>` in a source excerpt, body, status, member-resolved mentions, replies, resolve/reopen/delete controls, per-thread reply forms, and a select-then-compose form with member mentions. A returned offset is highlighted only when it still matches the loaded source; a mismatch prompts refresh instead of highlighting unrelated text. Detached threads show `Anchor unavailable: selected range changed.` with the body and replies intact and no highlight. Composer anchors are created from the server-loaded Yjs lineage (never a throwaway doc), and the loaded doc touches its root before use per the S08-T04 ordering finding. Mouse and keyboard selection events update the range before composing.
- The panel mounts in `ProjectWorkspace` for selected `FILE`/`TEXT` nodes only; other nodes keep the previous details view.
- Server range-following is covered at the API: an insertion before a range shifts reported `start`/`end` (7/13 → 11/17); rewriting the source detaches with `range_changed` while body, replies and mentions stay visible.
