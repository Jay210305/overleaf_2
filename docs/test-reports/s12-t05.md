## Implementation

New `apps/web/src/features/integrations/github-sync.tsx` (INT-05, consumer/core slice). It renders the frozen three-way sync plan produced by S12-T03/T08 as a base/local/remote diff and lets an authorized editor resolve every conflict explicitly:

- **Diff model.** `buildSyncDiffRows(plan)` maps the real S12-T03 classification output (`PullEntry.action`, `localKind`/`remoteKind`, fingerprints/SHA) plus the base agreement manifest into sorted rows with base/local/remote cells and the planner action. `unchanged` paths are omitted; conflicts that appear only in a minimal status view are synthesized as rows so no conflict becomes invisible. `summarizeSyncRows` reports additions/updates/deletions/kept/conflicts.
- **Resolution model.** `buildResolutionRequest(rows, decisions)` accepts only `keep-local`, `keep-remote` and `manual`, refuses a decision for a non-conflict path (`UNKNOWN_PATH`), refuses unknown decisions such as an attempted automatic force directive (`INVALID_DECISION`), and refuses to submit while a conflict is unresolved (`UNRESOLVED_CONFLICTS`). It returns the canonical apply paths (safe `add`/`update`/`delete` plus `keep-remote` conflicts) and never emits a force field or a push direction.
- **Honest state.** `deriveSyncUiState` is the single source of truth for the visible label: `error`, `syncing`, `sync_pending` and `conflict` transports are reported as such, and even a server `synced` transport is shown as `conflict` while a conflict is unresolved and as `sync_pending` while a `manual` merge is deferred. A pending, failed or manually deferred action can never render as "Synced".
- **UI.** `SyncResolutionView` renders the status badge, the base/local/remote columns, the per-conflict resolution selector (`keep-local`/`keep-remote`/`manual`), the unresolved-conflict warning and a guarded "Apply remote changes" action that stays disabled until every conflict is resolved. `GitHubSyncPanel` loads the authorized status through the typed client, owns the decision state and submits the resolved plan.
- **Typed client.** `createGitHubSyncClient` uses the documented routes `GET /api/v1/projects/{projectId}/integrations/github/status` and `POST …/integrations/github/sync` (`Idempotency-Key`, session CSRF, `credentials: include`). It validates UUIDs, the sync input and the idempotency key locally before any network call, maps provider/session failures to typed `GitHubSyncClientError` values, and rejects malformed responses (`502 INVALID_RESPONSE`).

Contract inputs used: the server-held OAuth connection, the explicit repo/branch, the frozen local revision and the expected remote SHA (`base` + plan). The `resolutions` array on the sync request is a proposed extension of the planned `SyncRequest` body; see Limits.
