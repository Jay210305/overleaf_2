# S12-T01 — GitHub OAuth credential handling

**Status:** DONE, accepted by the user as independent co-maintainer review on 2026-10-16. **Branch:** `codex/sprint-12-github-sync` tracking `origin/codex/sprint-12-github-sync`. **Base:** `0555e8d` (`origin/main` after the G2 docs commit). **Environment:** Windows, Node 24, pnpm 11.25.0, local PostgreSQL/Redis/MinIO. **Actual effort:** Not measured.

## Scope and acceptance evidence

- `POST /api/v1/integrations/github/start` (session) issues a single-use state plus a PKCE S256 challenge and returns a real provider authorize URL (`apps/api/src/modules/integrations/github-auth.ts`). No token exists at this point.
- `POST /api/v1/integrations/github/callback` consumes the state atomically (replay, foreign-user and expired states denied), exchanges the code through an injectable exchanger (production default posts to the configured token endpoint; 429 maps to RATE_LIMITED, other failures to PROVIDER_UNAVAILABLE, never a fake synced state), encrypts the token with AES-256-GCM and persists only the packed ciphertext in `external_connections.encrypted_credential_ref` (table from S01-T04, migration `0002-support.sql`). The response carries `connectionId`/`provider`/`scopes` only.
- `GET /api/v1/integrations/github/status` and `POST /api/v1/integrations/github/disconnect` never expose tokens; disconnect revokes best-effort and removes the row, then 404s.
- Without provider configuration (`githubAuthConfigFromEnv` finds no `GITHUB_CLIENT_ID`/`GITHUB_TOKEN_ENCRYPTION_KEY`), mutating endpoints answer 503 CREDENTIALS_MISSING and status answers `{ connected: false }`. No new required env vars; production startup is unchanged (`apps/api/src/main.ts`).
- DTOs added to `@latex-collab/contracts` (`githubConnectionViewSchema`, `githubOAuthStartResponseSchema`, `githubOAuthCallbackSchema`, `githubOAuthStatusSchema`).
- `tests/integration/s12-t01.test.ts` (9 tests): start/PKCE shape, session/origin/CSRF denials, connect without token leakage plus ciphertext round-trip, replay/foreign/invalid-state denials, cross-user binding, provider-failure mapping with no row created, 429 mapping, status/disconnect/revoke/404 cycle, unconfigured CREDENTIALS_MISSING.
- `tests/regression/int-05/s12-t01.test.ts` (2 tests): service `connect` returns a typed ProviderResult with link-only capabilities (`list/pull/push/individualReferenceImport` all false — linking and sync are S12-T02..T04); provider failure rejects instead of syncing.
- `tests/regression/nfr-10/s12-t01.test.ts` (1 test): token and its SHA-256 absent from every response body and the captured server log stream; no plaintext token at rest.
