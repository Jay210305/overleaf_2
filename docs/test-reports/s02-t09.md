# S02-T09 — Redacted audit event writer

**Status:** Implementation tested; independent co-maintainer review pending. **Branch:** `feature/identity-permissions` tracking `origin/feature/identity-permissions`. **Base:** accepted S02-T06 closure commit `7e54606` (sprint base `b75ef65`). **Environment:** Windows, Node 24, pnpm 11.25.0, local PostgreSQL 17. **Actual effort:** not measured.

## Scope and behavior

- `writeAuditEvent` inserts only three allowlisted actions (`account.created`, `session.login`, `session.revoked`) with a UUID request ID and an empty redacted metadata object. It accepts no arbitrary metadata, request body, password, token or source. The writer takes the caller's transaction so an audit failure rolls back its associated mutation.
- Trusted registration, successful login, logout and password-reset session revocation call the writer inside their PostgreSQL mutation transactions. The request ID comes from the server-generated Fastify ID. Registration's existing SMTP failure compensation also removes the provisional creation event. Denied CSRF, invalid credentials and consumed reset tokens create no events.
- This slice audits account creation and session actions. Future invitation, project download and restore features must add their own authorized events. Audit retention remains unspecified operational work under the data-model contract; no retention policy is claimed here.
