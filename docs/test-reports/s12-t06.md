# S12-T06 — Authorized revision exports and links

**Status:** implementation in progress; independent co-maintainer review pending. **Branch:** `codex/sprint-12-github-sync` tracking `origin/codex/sprint-12-github-sync`; base `0555e8d`. **Environment:** Windows 11, Node 24.20.0, pnpm 11.25.0; local PostgreSQL and private object storage for the revision ZIP boundary. **Actual effort:** not measured.

## Implementation

`apps/api/src/modules/exports/routes.ts` serves `GET /projects/{projectId}/revisions/{revisionId}/exports/{source|pdf|log}` and `POST .../exports/links`, then resolves an issued link at `GET /projects/{projectId}/exports/links/{linkId}`. The project guard checks the current session, Origin and membership for every request and CSRF for link creation. Source ZIP additionally requires OWNER/EDITOR. Selection binds one project-scoped immutable revision; PDF/log also bind one exact compile job with that `source_revision_id` and a retained artifact set. Private object reads use the server-owned project/job key and a 25 MiB bound. PDF requires a succeeded compile and `%PDF-` bytes. Source ZIP uses the existing frozen-revision `buildSourceZip` producer. The response never includes an object key or private source in link metadata.

Migration `0016-revision-export-links.sql` persists project, revision, optional compile job, kind, creator and one-hour expiry. The URL is an opaque link identifier, not an anonymous capability; every read rechecks current project authorization, export role, revision, retention and object key. An expired link returns 410. The task adds no TeX execution path.
