**Status:** IN_PROGRESS; implementation evidence prepared for independent co-maintainer review. **Branch:** `codex/sprint-08-sharing-comments-chat` tracking `origin/codex/sprint-08-sharing-comments-chat`. **Base:** `a568117` (`origin/main`, after S07). **Environment:** Windows, Node 24.20.0, pnpm 11.25.0, local Docker Compose PostgreSQL, Redis, MinIO and Mailpit. **Actual effort:** Not measured.

## Scope and acceptance evidence

- OWNER can invite an existing verified, enabled account as EDITOR, REVIEWER or VIEWER. Only the invited account can accept or reject. Owner can list and revoke project invitations. Foreign project and non-owner requests are denied.
- Each invitation has a random 32-byte one-use secret, stored only as a SHA-256 hash. The token travels in the request body and in an email URL fragment, rather than a path or query string. A replacement invite revokes the earlier one. Delivery failure leaves no redeemable invitation.
- PostgreSQL records invitation lifecycle timestamps and enforces one pending invitation per project and normalized email. Acceptance updates membership and consumes the invitation in one transaction; concurrent redemption, replay, expiry, revocation and stale reactivation are denied. Local SMTP delivery was inspected through Mailpit in an integration test.
- Integration and COL-04 regression tests use real PostgreSQL. Eleven focused assertions passed, covering delivery, cursor pagination, role and CSRF denial, wrong account, trusted account registry, expiry, rejection, revocation, replay and concurrency.
- Contract version 2.0.0 and ADR-010 record the token-in-body change from the planning baseline. The OpenAPI copies, typed DTOs, HTTP/collaboration/data contracts and rate limits were updated together.

The generic task template also mentions cross-project comments, links, revoked sockets and detached text anchors. Those behaviors belong to S08-T02, T04, T07 and T08. This report makes no acceptance claim for them or for the whole COL-04 feature or G2 gate.
