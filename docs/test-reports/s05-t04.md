## Scope and acceptance evidence

- `buildSourceZip(db, storage, { projectId, actorId, revisionNo })` exports one frozen revision: READ authorization (owner or current member; foreign, trashed, missing or malformed IDs read as 404), revision row plus non-deleted `revision_items` for the tree, TEXT bytes from canonical Yjs replay keyed by item `node_id`, BINARY bytes from content-addressed objects with key-equals-recomputed-hash enforcement (422 on mismatch or missing object). Revision paths are re-validated (traversal/absolute/empty segments are corruption, 422/400); entry, per-file and total caps reuse the shared archive limits (413). The builder now lives in `packages/storage/src/source-export.ts` (relocated from the jobs app so the S05-T05 export download route consumes the same implementation; behavior unchanged, S05-T04 suites re-verified against the new path).
- Deterministic writer: stored entries, UTF-8 names, fixed DOS timestamp, path-sorted files plus implied directory entries. No new dependency was added; the writer mirrors the shape the import validator already reads.
- `tests/integration/s05-t04.test.ts` (4 tests): exact-bytes export parsed back through the import validator with per-file hash/size agreement, byte-identical repeat exports, tree pinning across two revisions (a file added after rev 1 appears only in the rev-2 export), and foreign/trashed/unknown-revision/malformed-ID denials.
- `tests/regression/pro-06/s05-t04.test.ts`: export feeds a fresh reserve/enqueue/validate/apply cycle and the re-export carries identical file paths and hashes.
- `tests/regression/nfr-06/s05-t04.test.ts`: repeated exports are byte-identical and the export manifest hash recomputes exactly.
- Known scope limit, documented here and not tested: TEXT bytes are the canonical state observed during export (single-actor G1 flow). Revision rows do not store revision-time text bytes — `createStructuralRevision` records `sha256("")` for text items — so a concurrent edit between checkpoint and export would surface in the ZIP. Concurrent modification in the export flow is out of scope; the per-file hashes in the export manifest record exactly what was exported.
