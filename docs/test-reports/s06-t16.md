## Scope and acceptance evidence

- Implemented automated trusted backup and recovery utilities in `infra/scripts/trusted-backup.ts`:
  - `createTrustedBackup`: queries relational tables (`projects`, `project_revisions`, `revision_items`, `artifact_sets`), downloads all referenced object storage blobs into a directory, and creates `manifest.json` with SHA-256 checksums.
  - `restoreTrustedBackup`: validates bundle integrity and restores missing storage blobs to object storage.
  - `verifyBackupIntegrity`: scans database rows for referenced storage keys (`project_revisions.manifest_key`, `revision_items.blob_key`, `artifact_sets.pdf_key`, `log_key`, `synctex_key`) and verifies presence in object storage, enforcing the invariant that zero referenced blobs are missing.
- Authored comprehensive disaster recovery runbook in `docs/operations/g1-recovery.md` detailing:
  - Invariant definitions under NFR-09 and PL-04.
  - Pre-release backup snapshots and pre-release integrity verification.
  - Step-by-step rollback procedures for application services and data stores.
  - Post-rollback consistency verification and health probe checks (`/api/v1/health/live`, `/api/v1/health/ready`).
- Added integration and regression test suites:
  - `tests/integration/s06-t16.test.ts`: validates point-in-time backup bundle creation, data loss detection upon blob deletion, complete blob restoration, and zero-missing-blob recovery.
  - `tests/regression/nfr-09/s06-t16.test.ts`: verifies disaster recovery runbook defines consistent restore and zero dangling blob invariants, and that the backup utility exports all required functions.
  - `tests/regression/pl-04/s06-t16.test.ts`: verifies rollback procedures and health check references.
