# S09-T10 — Implement owned project tags

**Status:** IN_PROGRESS (task implementation complete; pending sprint completion). **Branch:** `codex/sprint-09-history-review` tracking `origin/codex/sprint-09-history-review`. **Base:** `main`. **Environment:** Linux (x86_64), Node 24+, pnpm 11.25.0, local Docker Compose PostgreSQL 17, Redis 7. **Actual effort:** 6 h.

## Scope and acceptance evidence

- Implemented user-owned colored tag management in `apps/api/src/modules/tags/routes.ts`:
  - `GET /api/v1/tags`: lists tags belonging strictly to the authenticated user.
  - `POST /api/v1/tags`: creates user-owned colored tag with duplicate name protection (returns 409 `TAG_CONFLICT`).
  - `PATCH /api/v1/tags/:tagId`: updates tag name/color ensuring user ownership.
  - `DELETE /api/v1/tags/:tagId`: deletes tag and cascades link removals.
  - `POST /api/v1/projects/:projectId/tags/:tagId`: links user's tag to project (many-to-many link via `project_tag_links`).
  - `DELETE /api/v1/projects/:projectId/tags/:tagId`: unlinks tag from project.
- Enhanced `ProjectRepository.list` in `packages/db/src/repositories/projects.ts` to support filtering by `tagId`, ensuring only projects linked to the authenticated user's tag are returned.
- Implemented accessible UI component `TagPicker` in `apps/web/src/features/projects/tag-picker.tsx` with color badges, tag toggling, and new tag creation.
- Added comprehensive test suites:
  - `tests/integration/s09-t10.test.ts`: exercises tag CRUD, duplicate name conflict, project linking/unlinking, pagination filtering by tagId, and strict user isolation.
  - `tests/regression/pro-09/s09-t10.test.ts`: verifies PRO-09 requirement for many-to-many tag linking and tag-based project filtering.
