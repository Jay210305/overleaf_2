## Scope and acceptance evidence

- Mounted the collaboration server on the production API listener with the same scoped ticket store used by the REST ticket route. The WebSocket server commits each update before room mutation, peer broadcast, and durable acknowledgement.
- Open WebSocket sessions now recheck the live database session, account, project, file and role before messages. Peer broadcasts recheck read access and close removed members before sending manuscript text. A demoted editor's stale write is denied and the socket closes with a reconnectable code so the client can obtain a read ticket. PostgreSQL-backed tests cover demotion, member removal and session revocation without depending on an external invalidation event.
- Connected CodeMirror and supported Visual heading, paragraph, list item, display formula, table cell, and figure text patches to one canonical Y.Text. The client obtains a scoped ticket, receives the persisted room state, exchanges updates, tracks pending writes until a covering durable acknowledgement, and retries after a connection loss. An unverified figure asset remains visibly unverified.
- Replaced the simulated Playwright test with two independent Edge contexts. Visual edits across these node types reach the Code editor and persisted text; a separate Code edit reaches the peer; an unknown macro remains byte-preserved. A concurrent same-heading Code edit causes the stale Visual draft to show conflict without overwriting source.
- Added comprehensive integration and regression test suites:
  - `tests/integration/s11-t09.test.ts`: exercises two clients on supported regions (paragraphs, display formulas, tables) converging cleanly; incompatible simultaneous edits on the same fragment trigger conflict rejection (`STALE_FRAGMENT_HASH`) and preserve source; mixed table and literal block additions maintain document invariants.
  - `tests/regression/edt-13/s11-t09.test.ts`: validates EDT-13 requirement that visual node edits converge with simultaneous code editor typing and table edits converge with concurrent TikZ additions.
  - `tests/regression/nfr-02/s11-t09.test.ts`: validates NFR-02 requirement that five simultaneous editors (spanning title code edits, visual abstract edits, visual table edits, visual math edits, and code appendix edits) converge to 100% byte-identical content with identical SHA-256 hashes.
