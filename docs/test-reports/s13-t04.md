# S13-T04 — Implement authorized manual Dropbox export

**Status:** PASS. **Branch:** `codex/sprint-13-reference-providers` tracking `origin/codex/sprint-13-reference-providers`. **Base:** `codex/sprint-11-visual-editor`. **Environment:** Linux (x86_64), Node 26+, pnpm 11.25.0. **Actual effort:** 8 h.

## Scope and acceptance evidence

- Implemented `DropboxExportAdapter` in `apps/jobs/src/sync/dropbox.ts`:
  - Implements the typed `ProviderAdapter` contract with `DROPBOX_EXPORT_CAPABILITIES` (`list: true`, `pull: false`, `push: true`, `individualReferenceImport: false`).
  - Pull operations are explicitly rejected with `CAPABILITY_UNSUPPORTED`, distinguishing manual export from bidirectional synchronization (owned by S13-T08).
  - Connect lifecycle handles valid Dropbox OAuth access tokens, empty tokens (`CREDENTIALS_MISSING`), expired tokens (`TOKEN_EXPIRED`), and provider throttling (`RATE_LIMITED`).
  - Remote folder enumeration via `listResources` returns destination folders.
  - Push export operation:
    - Publishes frozen authorized source revisions to the remote Dropbox target.
    - Compares `expectedRemoteRevision` against actual remote state and rejects out-of-sync exports with `REMOTE_CONFLICT` without silent overwrite.
    - Validates token status before upload and reports `TOKEN_EXPIRED` on expired or revoked credentials.
    - Records comprehensive audit trail: actor, project, provider, base revision, source revision, and result status.
    - Supports custom HTTP fetcher options to verify real Dropbox v2 API responses (including 401 token expiry, 409 write conflict, and 429 rate limit).
- Added comprehensive test suites:
  - `tests/integration/s13-t04.test.ts`: verifies capability model, connection lifecycle, resource listing, pull rejection, manual push export with audit logs, remote conflict detection, credential expiration/revocation, and HTTP fetcher responses.
  - `tests/regression/int-07/s13-t04.test.ts`: validates INT-07 conflict prevention and credential safety under expired tokens.
