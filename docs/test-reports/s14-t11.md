**Status:** PASS. **Branch:** `codex/sprint-14-git-and-optional-features` tracking `origin/codex/sprint-14-git-and-optional-features`. **Base:** `codex/sprint-13-reference-providers`. **Environment:** Linux (x86_64), Node 26+, pnpm 11.25.0. **Actual effort:** 8 h.

## Scope and acceptance evidence

- Implemented optional TOTP challenge and single-use recovery code consumption slice in `apps/api/src/modules/auth/totp.ts`:
  - `verifyTotpChallenge(tx, userId, code)`: Authenticates TOTP time-step challenge (with ±1 step skew window) or single-use 10-character alphanumeric recovery code. When a recovery code matches, it is atomically deleted from `user_mfa.recovery_codes` in Postgres, guaranteeing single-use semantics.
  - `challengeMfaLogin(tx, userId, code)`: Checks if MFA is configured for the user. If enabled and no code is provided, returns 403 `MFA_CODE_REQUIRED`. If code is provided, verifies via `verifyTotpChallenge` or returns 403 `INVALID_MFA_CODE`. Integrated into `POST /api/v1/auth/login`.
  - `disableMfaWithChallenge(tx, userId, currentSessionToken, code)`: Enforces verified TOTP or recovery challenge before unsetting MFA secret and deleting user recovery codes, and invalidates all other active sessions while keeping the current session intact.
- Verified interactions between active MFA and OAuth linking/unlinking (`tests/regression/acc-04/s14-t11.test.ts`), ensuring OAuth identities can be linked and unlinked safely without corrupting MFA secret or recovery state, and password logins continue enforcing MFA.
