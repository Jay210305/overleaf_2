# S02-T05 — Accessible authentication forms

**Status:** Implementation tested; independent co-maintainer review pending. **Branch:** `feature/identity-permissions` tracking `origin/feature/identity-permissions`. **Base:** accepted S02-T04 closure commit `471292d` (sprint base `b75ef65`). **Environment:** Windows, Node 24, pnpm 11.25.0, local PostgreSQL 17 and Mailpit, Edge browser. **Actual effort:** not measured.

## Scope and behavior

- The browser routes `/register`, `/verify-email`, `/login`, `/forgot-password` and `/reset-password` render labeled forms backed by the implemented HTTP API. The invitation remains operator issued; public signup stays unavailable. Invitation and email tokens are read from URL fragments and removed from the address bar before submission.
- Registration, verification, login, logout and recovery use the configured API, include cookie credentials and the required CSRF and invitation headers. The login page restores a cookie session after reload and keeps its CSRF value in memory for logout. In-flight session restoration is shared across React development Strict Mode effect runs so a second read does not invalidate the first rotation.
- The forms validate typed input, explain 400/401/403/429/503 and network failures, focus error/status messages, and prevent repeat submissions while pending. The forgot response is the same browser message for all accepted addresses. Password and token values are not written to browser storage.
