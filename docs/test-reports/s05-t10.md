## Scope and acceptance evidence

- `readArchiveForApply(bytes, expected)` in `apps/jobs/src/imports/zip.ts` reuses the validator's bounded scan, retains exact file bytes, and compares the recomputed manifest field by field (JSONB round-trips reorder keys, so no string comparison). Tampered version/hash, replaced bytes and folder/file collisions (`notes.tex` file plus `notes.tex/extra.tex`) fail with `ZipValidationError` and no partial map.
- `packages/db/migrations/0009-import-project-reservation.sql` adds nullable `pending_project_id` with no foreign key (the project does not exist at reservation time). `ImportJobRepository.reserveProjectId` sets it atomically with `COALESCE(pending_project_id, gen_random_uuid())` on validated jobs only; repeats converge. The ID stays on the internal `ImportApplyJobView` and never reaches the public job view.
- `prepareImportBlobs` in `apps/jobs/src/imports/apply-project.ts` writes manifest-declared binaries to deterministic `projects/<projectId>/blobs/<sha256>` keys and verifies returned size/SHA-256. Storage failure leaves the job validated with no project row; retries reconcile identical keys.
- `applyValidatedImport` re-reads the server-owned archive (size plus SHA-256 over a bounded read), re-verifies the full manifest, prepares blobs, then commits one transaction: project (owner/title from the job, `pdflatex`, revision 0), parent-before-child `FOLDER` (`inode/directory`) and `FILE` nodes, one seq-1 canonical Yjs `content` update per text file in `crdt_updates`, `main_file_id` (root `main.tex`, else first sorted `.tex`, else first sorted text), and the `succeeded` transition with the manifest retained for audit. A concurrent winner or duplicate call returns the existing project; anything else leaves no partial project and keeps the job validated.
- `runImportApplyPass` claims validated jobs oldest-first (`SKIP LOCKED`), applies them, fails jobs whose archives are confirmed missing or fail re-verification (`failApply` + archive sweep, mirroring the validation worker), and sweeps succeeded server-only archives past 14 days. Project blobs are never sweep targets. Re-verification failure is permanent for the row: replaced bytes, tampered manifests and validator drift never heal by retrying, and leaving such rows validated would wedge FIFO behind them. Transient storage outages count as retried.
- Bounded `imports:apply --once [--limit=N]` wired as `apps/jobs/src/imports/apply.ts` plus the `imports:apply` package script; `yjs` 13.6.27 added to `apps/jobs` (pinned, lockfile diff is exactly that addition).
- `tests/integration/s05-t10.test.ts` (14 tests): archive reopen/tamper/collision, one-ID reservation, storage-failure reservation retention, deterministic keys with no key leakage, consistent project creation with Yjs replay, duplicate/concurrent idempotency, replaced-bytes/tampered-manifest rejection with zero rows, mid-apply blob failure with zero rows/nodes, poisoned-job failing instead of wedging, and the bounded pass with 14-day sweep preserving project blobs.
- `tests/regression/pro-02/s05-t10.test.ts` (2 tests): nested folders/texts/binary applied with canonical replay and retry without duplication.
- `tests/regression/pro-10/s05-t10.test.ts` (4 tests): traversal, symlink and nested-ZIP archives fail validation and the apply pass leaves them failed with zero projects; a valid archive still validates afterward.
- Shared-service hygiene: suites run serially (`maxWorkers: 1`); the S05-T10 integration `beforeAll` removes validated fixture rows predating the file run (dependent intake rows first, per the completion-pair FK rule) so the bounded pass deterministically reaches its jobs. Other statuses are untouched. A probe during development found 655 stale validated rows from earlier sessions, including archive-missing ones the new fail path now retires.
