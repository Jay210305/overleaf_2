# S02-T10 — Authenticated password change

**Status:** Done; independent co-maintainer accepted on 2026-10-12. **Branch:** `feature/identity-permissions` tracking `origin/feature/identity-permissions`. **Base:** accepted S02-T07 closure commit `69b41c1` (sprint base `b75ef65`). **Environment:** Windows, Node 24, pnpm 11.25.0, local PostgreSQL 17, Redis 7, Mailpit and MinIO. **Actual effort:** not measured.

## Scope and behavior

- `POST /api/v1/me/password` requires the current verified, enabled account's opaque cookie, exact Origin and matching session CSRF secret. The strict body accepts the current password and an 8–128 character new password. The route validates the current Argon2id hash and rechecks the session, user and CSRF under PostgreSQL row locks before committing a replacement Argon2id hash.
- The same transaction consumes unused password-reset tokens, revokes all other sessions and writes one redacted audit event per revoked session. The initiating session remains valid. An incorrect current password returns 403 and leaves the hash and other sessions unchanged; malformed input returns 400, missing/expired session 401, disabled account/forged Origin or CSRF 403, and rate excess 429 with `Retry-After`.
- The static OpenAPI copies mark the operation IN_PROGRESS. Their password lengths now match the live registration/reset policy: the existing password may be 1–128 characters so older short credentials can be changed, while the new password must be 8–128. OpenAPI generation and DTO parity remain GAP-12.
