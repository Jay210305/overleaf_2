## Scope and acceptance evidence

- Implemented `detachAnchorsForChangedNodes` in `apps/api/src/modules/history/restore-metadata.ts` to detach relative-position comment anchors and mark pending suggestions on restored files as `conflict`.
- Integrated metadata detachment with `RestoreService.restore` in `apps/api/src/modules/history/restore.ts`, returning `detachedAnchorIds: string[]`.
- Verified invariant that content restore strictly preserves current project ownership, memberships, and revoked member status, ensuring historical restorations never revive revoked members or alter ACLs.
- Enforced server-side authorization: `POST /api/v1/projects/:projectId/restore` requires action `RESTORE`, permitted to OWNER and EDITOR; REVIEWER and VIEWER are rejected with 403.
- Added comprehensive test suites:
  - `tests/integration/s09-t06.test.ts`: exercises restore preserving current owner, memberships, revoked state, detaching comment anchors, marking suggestions conflicted, and rejecting REVIEWER restore requests.

  - `tests/regression/col-06/s09-t06.test.ts`: verifies COL-06 requirement that relative-position comment anchors become detached when content is restored.
  - `tests/regression/col-03/s09-t06.test.ts`: verifies COL-03 requirement that role authorization is enforced (EDITOR allowed, REVIEWER/VIEWER denied 403).
