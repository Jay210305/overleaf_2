# S02-T04 — Session and project policy guards

**Status:** Implemented and locally tested; independent co-maintainer review pending. **Branch:** `feature/identity-permissions` tracking `origin/feature/identity-permissions`. **Base:** accepted S02-T03 closure commit `05711b1` (sprint base `b75ef65`). **Environment:** Windows, Node 24, pnpm 11.25.0 via the installed CLI, PostgreSQL 17 and MinIO in local Compose. **Actual effort:** not measured.

## Scope and behavior

- `requireSession` verifies the exact Origin, hashed opaque cookie, seven-day idle and 30-day absolute expiry, revocation, enabled/verified account and session CSRF on mutations against current PostgreSQL state. It does not rotate tokens on ordinary project requests.
- The API installs a default-deny pre-handler for `/api/v1/projects/{projectId}/...`. A route must declare a server-owned action. The guard checks current owner or unrevoked membership for every request; malformed IDs return 400, absent/expired/revoked sessions 401, forged Origin/CSRF or denied actions 403, and absent/foreign projects 404 with no content. The handler receives the verified authorization result.
- The private `@latex-collab/auth` package contains a pure action matrix for OWNER, EDITOR, REVIEWER and VIEWER. Reviewer/viewer compile and source export default to false; the pure policy supports explicit capability flags, but the live guard grants none until persisted capability policy exists.
- The non-production development sample formerly selected the oldest project and could expose its metadata and stored sample object. It now selects only the named development fixture project. The production route remains absent.
