# Compilation parity: root document, includes and a worker in dev

Date: 2026-10-20. Scope: maintenance of the compilation worker and the local development stack (CMP-01, S06-T02, S06-T10, S06-T13). No task, sprint or release status change; independent co-maintainer review remains pending.

## Findings

Three defects kept a project from compiling the way it does in Overleaf:

1. The executor compiled a hardcoded `main.tex`. A project whose root document is `tesis.tex` failed with `Main source main.tex not found in revision`, even though the revision manifest already records `mainFileId`.
2. Outputs were collected only from `main.pdf`/`main.log`, so any other root document produced no artifact and the job was reported failed after a successful TeX run.
3. A project using `\include{chapters/capitulo_1}` stopped with `I can't write on file 'chapters/capitulo_1.aux'`: with `-outdir`, LaTeX writes included auxiliary files into `<outdir>/<include dir>`, which did not exist.

Additionally, `scripts/dev.ts` started only the API and the web app, so in local development compile jobs stayed `queued` (or `running` after a manual worker) with no worker to drain them; and diagnostics were parsed from latexmk's accumulated stdout, so warnings from earlier passes that the final pass resolved still surfaced as current problems.

## Changes

- `apps/jobs/src/compilation/trusted-worker-executor.ts`
  - `selectRootDocument(manifest)` resolves the root document from `mainFileId`, then `main.tex`, then the shallowest `.tex` item. The job fails only when no root document exists at all.
  - `compilationJobName()` derives the latexmk output base name (`tesis.tex` → `tesis`), and artifacts are read as `${jobName}.pdf` / `${jobName}.log` with an extension fallback.
  - Source subdirectories are mirrored inside the output directory before the run, so `\include` can write its `.aux` next to the job output.
  - latexmk is invoked with the relative root path from the compile directory, so `\input`, `\include`, `\includegraphics` and `\bibliography` resolve exactly as they do in Overleaf.
  - Diagnostics now come from the final `.log` when present, falling back to stdout only when no log was produced.
  - Hardened flags are unchanged: `-no-shell-escape`, `-interaction=nonstopmode`, `-file-line-error`, `-synctex=1`, sanitized environment, ephemeral workdir removed in `finally`.
- `scripts/dev.ts`: starts the compilation worker (`apps/jobs/src/main.ts`) alongside the API and web app, with `PORT` removed from its environment because it serves no HTTP. Compile jobs drain without a manual second terminal.
- `tests/integration/compiler-fixtures.test.ts`: covers the configured root document, included-file materialization, jobname-derived output collection, and root selection fallbacks.

## Known divergence from Overleaf

Shell escape stays disabled (`-no-shell-escape`, enforced by `tests/security/executor-isolation.test.ts`). Overleaf enables it, so packages and conversions that shell out are not available here: `minted` cannot run Pygments, and `epstopdf` cannot convert EPS on the fly. The compile log therefore contains `[epstopdf] Shell escape feature is not enabled`, which is accurate rather than a bug. Everything else exercised above (packages, `\include`, `\input`, images, BibTeX, reruns) behaves like Overleaf.

The guided visual-editor and SyncTeX round-trip are untouched by this slice; `-synctex=1` already produces the data file, but it is not collected as an artifact yet.
