# S14-T07 — Implement safe social OAuth account linking

**Status:** PASS. **Branch:** `codex/sprint-14-git-and-optional-features` tracking `origin/codex/sprint-14-git-and-optional-features`. **Base:** `codex/sprint-13-reference-providers`. **Environment:** Linux (x86_64), Node 26+, pnpm 11.25.0. **Actual effort:** 8 h.

## Scope and acceptance evidence

- Implemented safe OAuth account linking and callback flow in `apps/api/src/modules/auth/oauth.ts`:
  - `GET /api/v1/auth/oauth/:provider/start`: Validates provider against supported (`google`, `github`, `zotero`, `dropbox`) and unsupported/blocked sets (`mendeley`, `papers` return 422 `CAPABILITY_UNSUPPORTED`). Generates cryptographically secure state and PKCE `code_verifier` with SHA-256 `code_challenge`.
  - `GET /api/v1/auth/oauth/:provider/callback`: Validates single-use state and provider match. Exchanges code via pluggable resolver. For logged-in users, safely links identity to current user in `auth_identities` table while rejecting foreign identity collisions with 409 `IDENTITY_ALREADY_LINKED`. For unauthenticated users, matches existing identity or email, enforces `ACCOUNT_DISABLED` checks, and checks `PUBLIC_SIGNUP_ENABLED` policy before account creation.
  - `DELETE /api/v1/auth/oauth/:provider` & `DELETE /api/v1/me/identities/:provider`: Requires authenticated session with CSRF protection. Invariant check ensures user cannot unlink their sole authentication method if no password is set (returns 409 `CANNOT_UNLINK_LAST_AUTH_METHOD`).
  - `GET /api/v1/auth/oauth/identities`: Lists all currently linked providers and subjects for the authenticated user.
- Implemented foundation for MFA in `apps/api/src/modules/auth/mfa.ts`:
  - `POST /api/v1/me/mfa/setup`: Generates 20-byte cryptographically secure secret in base32 format and RFC 6238 compliant `otpauth://` URI with 10-minute setup TTL.
  - `POST /api/v1/me/mfa/confirm`: Validates 6-digit TOTP code, persists AES-256-GCM encrypted secret and generates 8 single-use recovery codes in `user_mfa` table.
  - `DELETE /api/v1/me/mfa`: Validates current TOTP code or recovery code, deletes MFA configuration, and revokes all other active user sessions while logging `session.revoked` audit events.
