**Status:** Accepted by the independent co-maintainer on 2026-10-11 in this conversation; S02-T02 done. **Branch:** `feature/identity-permissions` tracking `origin/feature/identity-permissions`. **Base:** accepted S02-T01 commit `b350cbc` (sprint base `b75ef65`). **Environment:** Windows, Node 24, pnpm 11.25.0 via the installed CLI, PostgreSQL 17 in local Compose. **Actual effort:** not measured.

## Scope and behavior

- Verified, enabled accounts can log in with their Argon2id password. Unknown accounts take a dummy Argon2 path; incorrect credentials return 401. The account is locked and rechecked before session insertion so a concurrent disable/password change cannot issue a session from stale data.
- The API sets a host-only opaque HttpOnly SameSite=Lax cookie. Production HTTPS adds `Secure` and the `__Host-` prefix; local HTTP uses `latex_session` without a Domain attribute. Only SHA-256 hashes of the session and separate CSRF secret persist in PostgreSQL. `0003-session-security.sql` adds creation time and CSRF hash; preexisting rows without a CSRF binding cannot authenticate.
- `GET /api/v1/auth/session` requires the exact Origin and a valid cookie, returns only the current account, and rotates both secrets in one locked transaction. Seven-day idle expiry is capped by 30-day absolute lifetime. `POST /api/v1/auth/logout` requires exact Origin and matching CSRF, persists revocation and clears the cookie. Invalid, expired and replayed cookies return 401; forged CSRF/Origin and disabled accounts return 403.
- The existing Fastify CORS policy now allows credentials only for the configured origin and exposes the CSRF response header. Authenticated project-role guards, session inventory, recovery and rate limiting remain later S02 tasks.
