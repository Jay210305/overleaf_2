## Scope and acceptance evidence

- Implemented private writing assistant interface contracts in `packages/contracts/src/writing-assistant.ts`:
  - `WritingAssistantRequest` and `WritingAssistantResponse` schemas enforcing strict fragment bounds (`MAX_FRAGMENT_LENGTH = 4000` characters; whole manuscript never transmitted).
  - Explicit user opt-in consent schema (`writingAssistantConsentSchema`).
  - `STATIC_LATEX_HELP`: comprehensive built-in offline explanation database for common LaTeX compiler errors (`Undefined control sequence`, `Missing $ inserted`, `Runaway argument`, etc.) operating without external transmission.
  - `MockWritingAssistantProvider` supporting `grammar`, `rephrase`, `autocomplete`, `explain_error`, and `summarize` modes.
- Implemented API route handlers in `apps/api/src/modules/assistance/routes.ts`:
  - Opt-in consent lifecycle (`GET` and `POST /api/v1/assistance/consent`): denies writing assistant requests with 403 `AI_CONSENT_REQUIRED` unless explicit user opt-in is recorded.
  - Offline static help endpoint (`GET /api/v1/assistance/static-help`).
  - Request assistance endpoint (`POST /api/v1/projects/:projectId/assistance`):
    - Validates server-side project permissions and request schemas.
    - Enforces bounded user quotas (50 requests/window) to prevent resource exhaustion.
    - Gracefully handles provider disconnects and unexpected errors by returning 200 with `fallbackAvailable: true` and relevant static LaTeX guidance, preserving editing flow without crashing or blocking.
