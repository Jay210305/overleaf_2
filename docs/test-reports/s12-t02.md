## Scope and acceptance evidence

- `GET /api/v1/integrations/github/repos?connectionId=` lists provider repositories through the caller's own active connection only (foreign IDs → 404); tokens stay server-side (`apps/api/src/modules/integrations/github-link.ts`).
- `POST /api/v1/integrations/github/link` supports explicit `import-new` (creates the project via the S03 `createProject` service, default title from the repo name) and `pair-existing` (caller must be project OWNER/EDITOR, otherwise 404; `projectId` with `import-new` or missing with `pair-existing` → 400).
- Linking compares the local tree manifest against the remote tree (`only-local`/`only-remote`/`differing`, sorted; `conflict` iff a same-path kind differs) and records `project_integrations` idempotently (`ON CONFLICT DO UPDATE`, no duplicate rows). Nothing is merged: an import-new project still contains only its fresh `main.tex`.
- `expectedRemoteSha` mismatch → 409 REMOTE_CONFLICT with nothing recorded; remote read happens before project creation, so failed links leave no orphan projects (asserted for stale/expired/down cases).
- Token expiry → 401 TOKEN_EXPIRED, provider failure → 502 PROVIDER_UNAVAILABLE, unconfigured → 503 CREDENTIALS_MISSING. No token in any response body.
- DTOs in `@latex-collab/contracts` (`githubRepoSchema`, `githubLinkInputSchema` with `owner/repo` shape, `githubManifestDiffSchema`, `githubLinkResultSchema`).
- `tests/integration/s12-t02.test.ts` (6 tests) and `tests/regression/int-05/s12-t02.test.ts` (2 comparison unit tests).
