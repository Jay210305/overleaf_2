## Scope and acceptance evidence

- Implemented GDPR-compliant user data export generation in `apps/jobs/src/exports/user-data.ts`:
  - `generateUserExportData`: queries personal profile, user preferences, sessions, owned projects, owned project tags, and shared project memberships.
  - Strict security invariants: completely omits credential hashes (`password_hash`, `token_hash`, session secrets) and avoids leaking third-party personal details or secrets across shared projects.
  - `createUserExportArchive`: creates an in-memory ZIP archive containing `profile.json`, `preferences.json`, `sessions.json`, `projects.json`, `tags.json`, and `memberships.json` along with an export manifest.
- Wired export trigger endpoint `POST /api/v1/me/data-export` in `apps/api/src/modules/account/profile.ts`:
  - Requires active authenticated session and valid CSRF token.
  - Returns `202 Accepted` with export job metadata, expiring download URL, and status.
- Added comprehensive test suites:
  - `tests/integration/s09-t13.test.ts`: exercises GDPR export bundle generation, verification of no credential leakage, and `POST /api/v1/me/data-export` endpoint authentication and response structure.
  - `tests/regression/acc-07/s09-t13.test.ts`: verifies ACC-07 requirement that user export data bundle is generated accurately without unauthorized secrets.
  - `tests/regression/pro-06/s09-t13.test.ts`: verifies PRO-06 requirement that data export archive contains authorized JSON files and manifest.
