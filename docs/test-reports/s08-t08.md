**Status:** DONE; user review confirmed 2026-10-15 in [sprint progress](../progress/sprint-08.md). **Branch:** `codex/sprint-08-sharing-comments-chat` tracking `origin/codex/sprint-08-sharing-comments-chat`. **Base:** `a568117` (`origin/main`, after S07). **Environment:** Windows, Node 24.20.0, pnpm 11.25.0, local PostgreSQL fixture. **Actual effort:** Not measured.

## Implemented and observed

- Found and closed the propagation gap: member removal, role change and share-link revocation committed the database denial but published nothing, so already-open collaboration sockets never learned about it. New `apps/api/src/modules/collab/invalidation.ts` publishes the collaboration service's own `RevocationEvent` shape to the `collab:invalidations` Redis channel it already subscribes; `member_removed` closes affected project sockets with 4403, `role_changed` downgrades demoted sockets to read-only. Events publish after commit; a publish failure is logged without secrets and never rolls back the denial. The chat WSS independently rechecks membership on every 1-second poll.
- Emit sites: `DELETE /projects/:id/members/:userId` (`member_removed`), `PATCH` role (`role_changed`), `DELETE /projects/:id/share-links/:linkId` (`member_removed` per link-derived grant). Production wiring in `main.ts` (create/close with the API lifecycle); fixtures default to a no-op publisher.
- Verified: expired invitations 410 with no membership, revoked/consumed/foreign invitations 404, rejected invitations consumed, revoked links 404 with derived grants revoked, expired/exhausted links 410, redemption bound to the source project, wrong-project comments 404, viewer writes 403, reply/resolve/reopen cycle intact, permission-aware delete (author/owner only), deleted ranges resolve to `detached`/`range_changed` with null offsets, and revoked members lose REST, collab-ticket and notification access.
- Contract slice documented in `docs/contracts/http-api.md` (G2 Sharing Revocation and Detached Anchors Slice).
