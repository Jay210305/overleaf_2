## Scope and acceptance evidence

- Conducted architectural and protocol research spike evaluating Git Smart HTTP protocols, security requirements, and revision mapping.
- Documented ADR-010 (`docs/adr/010-git-http.md`):
  - Selected Git Smart HTTP protocol (v1/v2) over deprecated Dumb HTTP.
  - Formulated the revocable scoped token authentication model: high-entropy Personal Access Tokens hashed with SHA-256 in the database; Basic auth support; separate `git:read` and `git:write` scopes; instant revocation.
  - Defined strict isolation: API session cookies and DB credentials are never exposed in Git bridge headers or responses.
  - Specified revision-to-commit bidirectional mapping: project revisions map to Git commits and tree objects; incoming pushes undergo strict fast-forward checks against the current project tip; stale pushes are rejected without silent overwrites.
  - Outlined canonical CRDT translation: incoming packfile text changes are applied through Yjs CRDT mutations to keep live web collaborators in sync.
  - Clarified boundary invariants: ZIP archive download is not equivalent to Git HTTP; real clone/fetch/push CLI interactions are required.
