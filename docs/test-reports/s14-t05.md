# S14-T05 — Deliver preference-controlled email notifications

**Status:** PASS. **Branch:** `codex/sprint-14-git-and-optional-features` tracking `origin/codex/sprint-14-git-and-optional-features`. **Base:** `codex/sprint-13-reference-providers`. **Environment:** Linux (x86_64), Node 26+, pnpm 11.25.0. **Actual effort:** 8 h.

## Scope and acceptance evidence

- Implemented preference-controlled notification email worker in `apps/jobs/src/notifications/email.ts`:
  - Supports all three core notification types: `mention`, `invite`, and `reply`.
  - Idempotent delivery tracking (`deliverNotificationEmail`): uses unique `eventId` deduplication to guarantee that replays or job retries deliver emails exactly once.
  - Granular user preferences check: honors user opt-ins/opt-outs for mentions, invites, and replies, suppressing delivery when the respective category is disabled.
  - Real-time project access authorization: checks active database project state and memberships for mentions and replies, suppressing notifications if the recipient was removed or lacks permission.
  - Multi-transport architecture: integrates `MailpitEmailTransport` for local development/testing with HTTP fallback, and `InMemoryEmailTransport` for isolated unit test verification.
- Developed `NotificationPreferencesPanel` in `apps/web/src/features/notifications/preferences.tsx`:
  - Accessible toggle controls for email and in-app notifications across mentions, invites, and thread replies.
  - Frequency selection (`immediate`, `daily_digest`, `off`).
  - Durable persistence with fallback to default settings upon corrupted or missing storage.
