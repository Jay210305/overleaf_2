## Scope and acceptance evidence

- Implemented read-only code/visual mode switching in `apps/web/src/features/visual/mode-switch.tsx`:
  - `useEditorModeSwitch`: Hook controlling switching between `"code"` and `"visual"` modes.
  - Zero-mutation guarantee: Captures canonical `initialSourceHash` on visual entry; switching back to code without user edits preserves 100% of bytes and SHA-256 hash identical.
  - Byte-level verification: `verifySourceByteFidelity()` confirms zero corruption or drift across any number of mode transitions.
  - Resilience against malformed syntax: Even documents with syntax errors or unclosed blocks preserve source bytes completely intact across mode transitions.
  - Active offset tracking: Retains cursor position and selection offsets across mode transitions.
  - Visual edit tracking: `recordVisualEdit()` and `hasUncommittedEdits` state track when user modifications have occurred.
  - `EditorModeSwitch`: Accessible UI component with `radiogroup` role, keyboard accessibility, active state styling, and syntax warning dot.
- Added comprehensive integration and regression test suites:
  - `tests/integration/s11-t07.test.ts`: exercises mode switch UI, source hash preservation without edits, resilience on broken syntax, and visual edit tracking.
  - `tests/regression/edt-13/s11-t07.test.ts`: validates EDT-13 invariant that multiple successive code-visual mode switches leave canonical source hash invariant.
