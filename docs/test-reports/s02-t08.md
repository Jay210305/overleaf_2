## Scope and observed behavior

- The new PostgreSQL-backed tests use synthetic project routes with declared server-owned actions. OWNER, EDITOR, REVIEWER and VIEWER can read an active project; EDITOR can edit. A live role downgrade immediately denies EDIT, revoking membership hides the project with 404, and another user's project ID returns 404 without the private marker. An archived project is hidden for normal reads, while owner restore is permitted and viewer restore is denied. An unconfigured project route is denied before its handler runs. Reviewer/viewer compiler and source-export probes remain denied without persisted capabilities.
- Account and project reads reject a revoked cookie with 401 and a disabled account with 403. Forged Origin and CSRF deny profile mutation without changing the database row. Session rotation invalidates the old cookie/CSRF pair; logout revokes the new pair. A forged-Origin password reset leaves its one-use token usable, while successful reset consumes the token and revokes the prior session.
- Captured real auth-route logs include request IDs but omit the tested cookie, CSRF secret, query token, email and private source marker. These are tests of the current application logger and routes, not a claim about future WSS, compiler, project CRUD or arbitrary application log calls. S02-T08 adds verification tests only; no production route, contract or migration changed.
