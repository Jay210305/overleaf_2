# S09-T11 — Implement permission-aware bulk project actions

**Status:** IN_PROGRESS (task implementation complete; pending sprint completion). **Branch:** `codex/sprint-09-history-review` tracking `origin/codex/sprint-09-history-review`. **Base:** `main`. **Environment:** Linux (x86_64), Node 24+, pnpm 11.25.0, local Docker Compose PostgreSQL 17, Redis 7. **Actual effort:** 6 h.

## Scope and acceptance evidence

- Implemented bulk project operations service and REST endpoint in `apps/api/src/modules/projects/bulk.ts`:
  - `POST /api/v1/projects/bulk`: accepts array of up to 100 `projectIds` and an action (`archive`, `trash`, `restore`, or `tag` with `tagId`).
  - Evaluates authorization independently per project: requires `OWNER` for lifecycle status changes (`archive`, `trash`, `restore`) and `OWNER`/`EDITOR` for `tag`.
  - Verifies tag ownership when action is `tag`, ensuring foreign tags cannot be attached.
  - Returns array of `{ projectId, ok: boolean, errorCode: string | null }`, guaranteeing one forbidden project never denies or masks mutations to authorized projects.
- Implemented accessible UI component `BulkActionsBar` in `apps/web/src/features/projects/bulk-actions.tsx` (`role="toolbar"`, clear selection, bulk archive, bulk trash, and bulk tag application).
- Added comprehensive test suites:
  - `tests/integration/s09-t11.test.ts`: exercises mixed batch of owned and viewer projects for bulk archive and bulk tag, confirming exact per-project success/denial reporting and database state integrity.
  - `tests/regression/pro-12/s09-t11.test.ts`: verifies PRO-12 requirement that bulk operations check permissions independently without leaking mutations to unauthorized projects.
  - `tests/regression/pro-09/s09-t11.test.ts`: verifies PRO-09 requirement linking multiple projects in bulk to a user-owned tag and validating tag filtering.
